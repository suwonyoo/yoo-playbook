# 원인에 근거한 디버깅

가장 짧은 실패 입력, 기대 결과, 실제 오류, 발생 위치를 먼저 잡는다. 긴 로그 전체 대신 관련 구간과 실행 명령을 남긴다.

한 번에 확인할 가설을 정하고 이를 구분할 관찰을 고른다. 예: 서버 응답 없음→프로세스/포트/바인딩, 잘못된 합계→필터/조인/분모, UI 미갱신→요청/상태/렌더링. 비밀 값은 출력하지 않는다.

원인을 설명하는 최소 변경 후 원래 실패 입력을 다시 실행한다. 새 변경이 주변 정상 동작을 깨지 않았는지 필요한 범위만 확인한다. 새 관찰 없이 같은 재설치·재시도를 반복하지 않는다. 해결이 길어지면 남은 시간과 필수 흐름을 기준으로 대안·축소 범위를 결정한다.

플랫폼 권한·모델·감독 장애라면 제약 우회 대신 발생 시각과 오류를 기록하고 제공된 신고 절차를 따른다.

출력: 증상, 확인한 원인 또는 아직 남은 가설, 변경 위치, 재현 전후 결과, 남은 위험.
