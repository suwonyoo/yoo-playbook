# 동작 검증

검증할 주장을 먼저 적는다. 컴파일·HTTP 응답·UI 동작·업무 계산·저장은 서로 다른 주장이다.

- 요구사항별 기대 결과와 판정 기준을 실행 전에 정한다.
- 정상 사례와 의미 있는 경계·오류 사례를 선택한다. 변경과 무관한 전체 테스트 반복은 피한다.
- 테스트 명령의 종료 코드와 실제 출력, 대상 코드·입력 버전을 남긴다. 하네스 사용 시 관련 소스·입력 파일을 `--track`으로 지정한다.
- UI는 사람이 제공 Browser에서 수행할 단계와 기대 결과를 제시하고 실제 관찰을 기다린다. 대신 조작하거나 관찰하지 않은 것을 통과로 쓰지 않는다.
- 테스트 실패, 미실행, 부분 확인을 그대로 기록한다. 코드 변경 후 관련 증거가 낡았으면 다시 확인한다.

출력: 요구사항 ID→검증 ID→입력/기대/실제/근거/판정. 테스트 개수보다 어떤 실패 가능성을 확인했는지 설명한다. 명령 종료 0만으로 전체 과제 완료를 선언하지 않는다.
