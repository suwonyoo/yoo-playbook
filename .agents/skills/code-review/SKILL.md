# 변경 검토

현재 diff, 호출 경로, 요구사항과 관련 검증을 읽는다. 리뷰만 요청받았다면 바로 수정하지 않는다.

입력 검증, 계산·단위, 상태 갱신, 저장 범위, 오류 처리, 사용자 흐름의 빠진 연결을 우선 본다. 신뢰할 수 없는 문자열을 HTML·SQL·셸에 직접 삽입하는지, 비밀을 노출하는지도 관련 코드에서 확인한다. 과제와 무관한 대규모 보안 감사로 확대하지 않는다.

발견 사항마다 재현 조건, 영향, 위치, 수정 방향을 적는다. 스타일 취향과 재현 가능한 결함을 구분한다. 문제가 없으면 검토 범위와 실행하지 않은 검증을 명시한다. 작성자의 완료 보고를 독립 검증으로 취급하지 않는다.
