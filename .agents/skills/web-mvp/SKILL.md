# 핵심 흐름 구현

과제의 기존 스택·요구사항을 우선한다. 필요하지 않은 인증·외부 API·신규 프레임워크를 추가하지 않는다.

1. 한 사용자의 입력→검증→처리→결과→저장 중 필요한 경로를 고른다. 작은 실제 데이터나 명확히 표시한 연습 데이터로 먼저 연결한다.
2. 상태와 계산의 주인을 정한다. 같은 값이 UI와 서버에서 다르게 계산되지 않게 한다. 저장 범위가 메모리/브라우저/서버 중 무엇인지 명시한다.
3. 빈 결과, 잘못된 입력, 처리 중, 실패, 성공 상태를 사용자가 이해할 문구로 표현한다. 오류를 성공 메시지로 덮지 않는다.
4. 라벨·키보드 포커스·읽을 수 있는 숫자와 단위를 갖춘 화면을 만든다. 기존 디자인 체계가 있으면 따른다.
5. 서버를 실제 포트와 0.0.0.0에 연결하고 유지한다. HTTP 확인과 사람의 Browser 조작 확인을 구분한다. 실전에서 브라우저 자동 조작 도구를 호출하지 않는다.

출력: 구현한 요구사항, 변경 위치, 실행법, 검증 결과, 저장·데이터의 한계. 화면만 만들어 놓고 계산·저장이 구현됐다고 보고하지 않는다.
