# 병렬 작업 운영

요청된 범위와 환경 지원을 확인한다. 도구가 없으면 단일 에이전트와 별도 서버·테스트 터미널로 수행한다. 병렬화를 위해 외부 AI 서비스나 개인 계정을 연결하지 않는다.

읽기·리뷰는 공유해도 되지만 동일 파일의 동시 작성자는 한 명으로 제한한다. 의존성이 큰 API 계약·스키마는 먼저 합의한다. 공유 파일, 패키지 설치, lockfile 변경, 통합은 주 에이전트가 맡는다.

위임마다 목표, 입력, 수정 허용 경로, 금지 경로, 완료 조건, 반환할 근거를 전달한다. 이름만 다른 에이전트에게 같은 문제를 중복 수행시키지 않는다. 독립 브랜치·worktree를 쓰면 통합 시간과 파일이 실제 제출 폴더에 들어왔는지도 고려한다.

주 에이전트는 결과 diff와 검증을 확인하고 통합한다. 파일 충돌·메모리 압박·대기 비용이 늘면 동시 작업 수를 줄인다. 더 많은 에이전트가 더 빠르거나 토큰을 절약한다고 보장하지 않는다.
