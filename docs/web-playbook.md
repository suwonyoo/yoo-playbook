# 웹 서비스 과제 플레이북

웹 과제일 때만 읽는다. 실제 제공 스택과 제출 조건이 우선이다.

## 첫 흐름

사용자 한 명의 핵심 행동을 정한다. 예: 조건 입력→목록 필터→상세 결과→판단. 실제 과제가 확정되기 전의 예시다. 데이터 파일이 있으면 열·단위를 확인하고 작은 대표 입력으로 끝까지 연결한다. UI, API, 저장소를 각각 완성한 뒤 처음 연결하는 방식은 통합 오류를 늦게 발견하게 된다.

| 부분 | 먼저 정할 것 | 확인 방법 |
|---|---|---|
| 입력 | 필수값·범위·기본값 | 빈값·경계·형식 오류 |
| 처리 | 계산 규칙·정렬·중복 | 손계산 표와 결과 비교 |
| 결과 | 단위·필터·기준 시점 | 입력 변경 시 결과 변경 |
| 상태 | 로딩·빈 결과·실패 | 실패가 성공으로 표시되지 않음 |
| 저장 | 저장 위치와 유지 범위 | 새로고침·재실행 요구에 맞는 검증 |

## 서버와 미리보기

프레임워크의 실제 명령을 확인한다. Vite 프로젝트라면 `npm run dev -- --host 0.0.0.0`처럼 설정할 수 있지만 다른 프레임워크에 그대로 적용하지 않는다. 플랫폼 Browser에 터미널의 실제 포트와 경로를 입력한다. 개발 서버의 터미널은 유지한다.

`curl -f http://127.0.0.1:실제포트/`는 HTTP 응답 확인이다. 버튼·오류 문구·정렬·저장 동작은 사람이 플랫폼 Browser에서 직접 확인한다. 자동 브라우저 조작·외부 터널·배포가 필요하다고 가정하지 않는다.

## 시간이 부족할 때

요구된 핵심 흐름을 남기고 장식·부가 기능을 줄인다. 단, 필수 기능을 말없이 삭제하지 않는다. 인증·실시간 협업·복잡한 상태관리·외부 API는 요구에 근거가 있을 때 도입한다. 샘플 데이터만 동작하면 그 범위를 명시한다.

## 제출 직전

실제 시작 명령, 설치 의존성, 기본 경로, 데이터 위치, 지원 범위가 README와 일치하는지 확인한다. 과제에 필요한 소스가 `/tmp`나 별도 worktree에만 남아 있지 않도록 실제 제출 폴더를 확인한다.
