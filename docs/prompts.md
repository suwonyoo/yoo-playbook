# 상황별 요청문

아래는 범용 출발점이다. 실제 과제 파일명과 요구사항을 반영한다. 실제 후속 서술형 단계에서 답안을 생성하는 용도로 사용하지 않는다.

## 시작

> 과제 README, 현재 AGENTS.md와 제공 파일을 읽어줘. 필수 기능·제출물·성공 확인 방법을 요구사항 ID로 정리하고, 사실과 가정을 구분해줘. 가장 중요한 사용자 흐름 하나부터 구현하고 검증해줘. 불필요한 도구 설치는 피하고 기존 스택을 우선해줘.

## 업무 담당자에게 물을 질문 준비

> 구현 방향을 바꾸는 업무 정의만 골라 질문 초안을 만들어줘. 질문마다 현재 가정, 다른 답일 때 바뀌는 부분을 붙여줘. 단순 도구 사용법·오류 신고는 분리해줘. 내가 보낼 질문을 준비하는 작업이며 대신 전송하지 마.

## 병렬 위임을 명시적으로 요청할 때

> 지원되는 서브에이전트가 있으면 독립 작업을 나눠줘. 한 명은 요구사항 누락을 읽기 전용으로 검토하고, 다른 한 명은 지정한 테스트 파일만 담당해줘. 주 에이전트는 구현·공유 설정·통합을 맡아줘. 허용 파일, 완료 조건, 검증 명령을 전달하고 결과를 직접 확인해줘.

## 동작 확인

> R-001의 성공을 확인할 정상·경계·오류 사례를 골라줘. 자동 테스트와 내가 Browser에서 직접 할 행동을 나눠줘. 실행한 결과만 기록하고, 테스트의 종료 코드·로그·관련 파일을 연결해줘. 아직 내가 확인하지 않은 화면은 미확인으로 남겨줘.

## 판단과 협업 기록

> 지금까지 실제로 한 요청·수정·검증을 근거로 기록을 갱신해줘. AI 제안, 내가 선택한 이유, 확인 방법, 실제 결과, 한계를 구분해줘. 대화에 없는 판단이나 직접 확인은 만들어 넣지 마.

## 실패 대응

> 이 실패를 가장 짧게 재현하고 기대/실제 결과를 비교해줘. 원인 후보를 구분할 관찰을 먼저 선택하고 한 번에 작은 변경만 해줘. 원래 실패와 관련 정상 흐름을 재검증해줘. 같은 조치를 근거 없이 반복하지 마.

## 인수인계

> 현재 목표, 완료한 기능, 실제 파일 위치, 마지막 검증, 실패 재현, 실행 중인 서버, 다음 행동 3개 이내를 .playbook/handoff.md에 정리해줘. 다음 세션이 기록과 현재 파일을 대조할 수 있게 근거 경로를 넣어줘.

## 제출 전

> 실제 제출 요구와 현재 파일·문서·검증을 대조해줘. 필수 누락과 확인되지 않은 주장을 우선 알려줘. 제출 클릭은 내가 할게. 설명 문서의 기능·한계가 실제 구현과 일치하는지 확인해줘.

## 사전 설명 연습

> 지금은 시험 전 연습이야. 이 연습 프로젝트의 실제 기록으로 핵심 동작, AI 제안 검증, 대안 선택, 한계를 하나씩 질문해줘. 내가 먼저 답하면 사실성·근거·명확성을 피드백해줘. 실제 시험 문제를 예측하거나 없는 경험을 만들어 주지는 마.
