# 데이터·분석 과제 플레이북

분석·집계·추천·예측이 필요한 과제일 때 읽는다. 모델 학습이 필수라는 전제는 두지 않는다.

## 먼저 물을 질문

이 행은 무엇 하나를 뜻하는가? 식별 키는 유일한가? 날짜의 기준·시간대는 무엇인가? 누락이 0과 같은 의미인가? 지표의 분모는 전체·유효·선택 중 무엇인가? 평가 시점에 알 수 없는 정보가 입력에 섞였는가?

## 작은 검산 예시

그룹 A는 성공 1/2, 그룹 B는 성공 9/18이다. 전체 성공률은 (1+9)/(2+18)=50%다. 다른 예로 A=1/1, B=0/9이면 그룹 비율의 단순 평균은 50%지만 전체 성공률은 10%다. 어느 정의가 필요한지 업무 기준으로 결정한다.

조인할 때는 왼쪽 키 A가 두 번, 오른쪽 키 A가 세 번이면 결과가 여섯 행이 될 수 있다. 조인 전후 행 수와 유일 키 수를 기록하고 의도한 다대다 관계인지 확인한다.

## 추천·예측이 필요한 경우

- 규칙 기반 기준선으로 목표 지표를 계산하고 모델의 추가 가치가 필요한지 판단한다.
- 시간 순서가 있는 데이터는 미래 정보 누출을 막는 분할을 고려한다. 같은 개체가 여러 행이면 개체가 양쪽에 섞이는지도 확인한다.
- 정확도만 쓰지 말고 문제에 맞는 지표와 오류 비용을 설명한다. 불균형·작은 검증 표본의 한계를 기록한다.
- 전처리·필터·seed·학습/검증 구분을 남긴다. 전 데이터를 사용해 전처리를 학습한 뒤 분할하지 않는다.
- 과제에서 허용한 로컬 도구로 처리한다. 외부 모델 API로 데이터를 전송하지 않는다.

## 산출물

입력 구조, 가공 기준, 계산 정의, 결과 표·그림, 검증 사례, 제한을 연결한다. 상관관계를 원인으로 단정하거나 검증하지 않은 개선율을 제시하지 않는다. 대시보드는 선택 필터와 분모를 화면에 표시한다.
