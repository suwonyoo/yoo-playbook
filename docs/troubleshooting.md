# 막혔을 때의 확인 순서

| 증상 | 확인할 것 | 다음 행동 |
|---|---|---|
| Codex가 멈춘 듯함 | 승인 대기/명령 실행/서버 유지 구분 | 승인 질문은 내용을 보고 응답; 실행 중이면 동일 요청 중복 금지 |
| Browser 응답 없음 | 본인 서버 오류→실제 포트→0.0.0.0→경로 | 본인 서버를 수정하고 플랫폼 Browser로 재확인 |
| 새 파일이 안 보임 | 디스크 존재와 탐색기 갱신 | 탐색기 새로고침; 파일을 중복 생성하지 않음 |
| 에디터 저장 충돌 | 외부 수정과 미저장 편집 비교 | 필요한 내용을 보존하고 저장 상태 재확인 |
| 패키지 설치 실패 | lockfile·기존 의존성·오류 문구 | 설치를 반복하지 말고 기존 도구 대안 검토 |
| 계산 결과 이상 | 원본·단위·필터·조인·분모 | 작은 손계산 예제로 단계별 비교 |
| 터미널이 너무 느림 | 플랫폼 CPU/RAM, 본인이 시작한 작업 수 | 중복 빌드·테스트 정리; 관리 프로세스는 변경 금지 |
| 서브에이전트 메뉴 없음 | 현재 버전과 제공 도구 | 단일 세션으로 수행; 관리자 설정 우회 금지 |
| 모델/API 오류 반복 | 발생 시각·오류·단계 | 플랫폼 문제 신고; 외부 AI로 전환하지 않음 |
| 제출 후 수정 필요 | 제출물 확정 여부 | 확정 후 변경 불가; 실제 구현과 한계를 설명 |

프로세스를 정리할 때 `killall node`, `pkill python`처럼 넓게 종료하지 않는다. 직접 시작한 PID나 해당 터미널만 다룬다. 감독·연결 프로세스를 종료하지 않는다.

시간이 부족하면 남은 필수조건과 검증 비용을 적고 가장 중요한 흐름을 우선한다. 문제 신고나 재접속이 타이머를 멈춘다고 가정하지 않는다.
